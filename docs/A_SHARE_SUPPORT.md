# A 股支持与数据边界

更新：2026-11-04。A 股作为现有 FinSight AI 的独立市场接入，继续使用 Vue 3 / TypeScript、FastAPI、PostgreSQL 和 Redis/RQ。美股 SEC 的路由、CIK、财务计算、来源版本与研究功能保留。实际命令、线上探测、队列、浏览器和测试结果统一见[测试记录](TEST_RESULTS.md)；本文件描述实现及使用方法，不预填尚未完成的验收结果。

## 数据来源

结构化财务取自东方财富公开网站使用的数据端点，属于**第三方整理数据**，不能称作交易所原始 XBRL 或本应用已逐项核对的原始财报事实。公司目录和公告来自[巨潮资讯网](https://www.cninfo.com.cn/)，原文链接指向巨潮的实际 PDF 披露文件。

| 内容 | 固定来源与处理方式 |
|---|---|
| 公司目录 | `https://www.cninfo.com.cn/new/data/szse_stock.json`；只接受 `category=A股` 的条目，排除 B 股及其他类别 |
| 财务指标/三表 | `https://datacenter-web.eastmoney.com/api/data/v1/get`；先按主要指标中的 `ORG_TYPE` 选择完整三表模板 |
| 定期报告公告 | `https://www.cninfo.com.cn/new/hisAnnouncement/query`；按所选证券代码、目录确认的 `orgId` 和定期报告类别查询 |
| 公告原文 | 只从响应中的受控 `finalpage/日期/数字.PDF` 路径生成 `https://static.cninfo.com.cn/` 链接；不猜文件名 |

财务模板为 `RPT_F10_FINANCE_MAINFINADATA` 加上以下三表，避免将银行、保险或证券公司套进一般企业字段：

| `ORG_TYPE` | 模板前缀 | 三张表 |
|---|---|---|
| 通用 | `G` | `RPT_F10_FINANCE_GINCOME` / `GBALANCE` / `GCASHFLOW` |
| 银行 | `B` | `RPT_F10_FINANCE_BINCOME` / `BBALANCE` / `BCASHFLOW` |
| 保险 | `I` | `RPT_F10_FINANCE_IINCOME` / `IBALANCE` / `ICASHFLOW` |
| 证券 | `S` | `RPT_F10_FINANCE_SINCOME` / `SBALANCE` / `SCASHFLOW` |

未知模板明确报错，不自动用通用模板补空。实现参考了[AKShare 官方三表源码](https://github.com/akfamily/akshare/blob/main/akshare/stock/finance/stock_three_report_em.py)中对东方财富报表及公司类型的处理；本项目直接使用已有 HTTP/Decimal 依赖，没有引入 AKShare 或 pandas。开源客户端代码的许可不等于上游金融数据的商业授权。

这些公开网站接口并非本应用可以保证稳定性的商业服务合同，可能改变字段、限制访问或暂停提供数据。当前获取链路没有要求用户提供 A 股 API Key 或联系邮箱；这不构成长期免费、全量覆盖或商业再分发许可的保证。源码交付包不包含本次抓取的东方财富原始响应；部署者应按自身使用范围取得数据并遵守来源站点的要求。

## 财务口径

### 年度和年初累计

`annual` 只使用报告期末为 12 月 31 日的年度记录。`cumulative` 使用 3 月 31 日、6 月 30 日、9 月 30 日、12 月 31 日的报告记录；收入、利润、每股收益与现金流保持当年 1 月 1 日起的累计值。资产、负债、权益、货币资金及期末现金等价物为期末时点值。

例如，半年累计收入不会被直接标成第二季度收入，全年 EPS 也不会减去前三季 EPS。现阶段不提供 `quarterly`，不将累计曲线当成四个独立季度或把累计金额相加。界面允许查看不同累计期，但跨年比较应使用相同报告期长度。

当前选择策略为 `latest_provider_snapshot`：使用本地当前发布的供应商响应批次。上游可能已经重述或更新历史数据；抓取时间、公告日期和报告期是不同字段。保存不可变响应并不意味着已重建历史当时能看到的数据。`as_of`、`as_filed` 及 SEC accession 参数在 A 股接口明确拒绝，不能用它做未实现的历史回测口径。

### 指标含义

| 指标 | 来源字段或计算规则 | 保护措施 |
|---|---|---|
| 营业总收入 | 利润表 `TOTAL_OPERATE_INCOME`；缺失时可取主要指标 `TOTALOPERATEREVE` | 与 `OPERATE_INCOME` 营业收入分开；金融类常有不同结构，不强行改名 |
| 营业收入 | 利润表 `OPERATE_INCOME` | 不用营业总收入替代缺失字段 |
| 净利润（供应商报表口径） | 利润表 `NETPROFIT` | 不用归母净利润或税前利润减税费擅自补齐 |
| 归母净利润 | 利润表 `PARENT_NETPROFIT` | 与报表净利润单独展示 |
| 营业利润（中国报表口径） | 利润表 `OPERATE_PROFIT` | 使用独立指标键，不视为 US GAAP operating income 的等价转换 |
| 经营活动现金流量净额 | 现金流量表 `NETCASH_OPERATE` | 中期为年初累计，不作单季差分 |
| 总资产、总负债、股东权益 | 资产负债表 `TOTAL_ASSETS` / `TOTAL_LIABILITIES` / `TOTAL_EQUITY` | 使用期末时点；权益仍标注供应商报表口径 |
| 货币资金 | 资产负债表 `MONETARYFUNDS` | 不与现金及现金等价物混用 |
| 期末现金及现金等价物 | 现金流量表 `END_CCE` | 缺失时不以货币资金补齐 |
| 基本/稀释 EPS | 利润表 `BASIC_EPS` / `DILUTED_EPS`，可分别读取主要指标 `EPSJB` / `EPSXS` | 两种 EPS 不互相替代，不作累计差分；单位为 `CNY/shares` |
| 毛利润、毛利率 | 一般企业同张利润表、同期间的营业收入减营业成本；毛利率再除以营业收入 | 银行、保险、证券及类型未知时不猜毛利，不跨表凑操作数 |
| 报表净利润 / 营业总收入 | 同一来源记录的 `NETPROFIT / TOTAL_OPERATE_INCOME × 100` | 总收入来自其他表的 fallback 时，不据此跨表推导比率 |
| 营业利润 / 营业总收入 | 同一来源记录的中国报表营业利润除以营业总收入 | 保留中国报表含义及全部操作数 |
| 资产负债率 | 同张资产负债表负债除以资产 | 分母必须为正，不以缺失值当零 |

供应商报表的合并/母公司范围尚未逐份与 PDF 核验。直接指标保留 `statement_scope=provider_reported_not_independently_verified`，不声称所有公司、所有历史记录的合并范围均已独立确认。中国准则及供应商同名指标也不自动与美股同名指标完全可比。

数字在 JSON 解码时使用 `Decimal`，原始值以十进制字符串返回，界面按字符串添加千位分隔。只有图形坐标使用近似数值转换，不能反过来替换表格或来源中的精确字符串。金额单位为人民币元；图表缩放单位明确显示，EPS、百分比和金额不混用一根尺度。

同比只比较同一证券、同一指标和同一年度/累计期的上一年同期；不拿前一季或前一个可用年份替代。基期为零或负数、上年同期缺失、字段或供应商组织类型不兼容时显示原因。派生百分比不再计算“同比百分比”。增长率和比率按 `ROUND_HALF_UP` 保留 8 位小数，并记录当前与对比操作数。

字段缺失、重复记录冲突、分母不适用等保持 `N/A`；不估算填补。整张必需财务表为空、公司/币种不符或期间无效则拒绝发布新批次并保留旧资料，不以包含大量空值的指标列表冒充完整同步成功。

## 北交所新旧代码

北交所历史公告可能仍使用原 `4`/`8` 开头代码，新证券标识则使用 `920` 号段。当前公告查询沿用巨潮公开接口的 `szse` 栏目；不能把 `column=bse` 返回的空列表当成该公司没有报告。

只有当前所选证券为 `.BJ`，且响应 `orgId` 与目录确认的公司 `orgId` 完全一致时，才接受其历史北交所代码。响应原代码与组织标识保存在 `source_security_code`、`source_org_id`；不会仅凭中文名称相似或代码相近合并公司，也不把这一规则用于沪深证券。目录可能保留旧证券标识，使用者仍需核对原始公告身份。

## 独立表和数据模式

新增迁移 `f51a01` 创建四张独立表：

- `cn_companies`：交易所限定的证券代码、名称、巨潮组织标识、目录与财务状态。
- `cn_source_snapshots`：按目录或证券范围保存原始响应版本、哈希、请求来源和时间。
- `cn_sync_jobs`：目录/公司的持久化任务、错误和执行状态。
- `cn_dataset_metadata`：A 股数据模式绑定。

美股的 `companies`、CIK、SEC 来源表、申报及研究表继续独立。A 股不把六位证券代码填入 CIK，也不调用 SEC 的正文/引用验证链。

| 配置 | 含义 |
|---|---|
| `CN_DATA_MODE=cn_live` | 允许授权后实际向固定 A 股来源端点获取数据 |
| `CN_DATA_MODE=cn_snapshot` | 仅显式导入可信本地真实归档；在线目录和公司同步被拒绝 |
| `synthetic_fixture` | 仅用于独立测试数据库，不能混入真实数据模式 |
| `DATA_MODE=synthetic_fixture` | 测试环境强制 A 股也使用夹具模式，覆盖 `CN_DATA_MODE` 并禁止在线同步 |

SEC 的 `DATA_MODE` 与 A 股的 `CN_DATA_MODE` 分别绑定，允许同一应用保留 SEC 历史演示并使用 A 股在线资料。第一次访问/初始化 A 股表时写入绑定，之后更换模式会明确报错；请用独立数据库/部署实例保存另一种 A 股模式，不修改或删除绑定来混装资料。API 和 worker 必须使用相同连接与配置。

## 分页、快照和任务

每种财务资源按每页 60 条、最多 6 页获取。客户端检查页数、总量、重复期间、公司身份及币种；超过同步上限或分页中总量发生变化时失败，不把截断历史静默当完整资料。财务与公告的发布时间不同，整个 HTTP 批次也不是上游数据库提供的原子事务快照。

每一页原始字节单独保存 SHA-256、首个抓取时间、请求 URL/参数及分页信息。同字节再次观察时复用原版本，更新 `last_observed_at`，不伪造新的首次抓取时间。公司当前使用的所有页 ID 在 `source_metadata.current_source_ids` 清单中一次发布；查询只读取该清单，不能各自挑“最后一页”或拼接多个同步批次。

指标还保留实际贡献该记录的页 ID、来源字段、哈希、时间和计算操作数。清单内页缺失或身份不符时明确失败。目录刷新与财务发布使用公司行锁并刷新 ORM 状态，保护两种来源清单不被旧 JSON 覆盖；旧原始响应继续保留。

浏览器写操作先创建持久化任务，Redis 仅传 `job_id`，由现有 `finsight` 队列的 Linux RQ worker 执行。重复提交复用有效任务，异常终态保留可读错误；网络失败、限流及验证失败不会把旧财务换成演示数据。目录和公司更新均需管理员会话权限。公开读取已保存资料不触发隐式下载或模型调用。

公告查询当前最多获取最近 100 条定期报告类别的响应，界面分页仅对已保存条目分页，不代表无限翻页远程获取或覆盖全部历史。公告标题、披露日期、报告期、正文是否解析是不同状态；原文链接存在不表示已完成 PDF 解析、证据验证或 AI 研究。

## 启动与使用

依赖和各平台运行前提沿用[部署指南](DEPLOYMENT.md)。已有 `.env` 不要覆盖，保留原数据库密码、管理员令牌和 SEC 配置，仅补充所需选项：

```dotenv
CN_DATA_MODE=cn_live
CN_TIMEOUT_SECONDS=20
CN_MAX_BYTES=10000000
TASK_MODE=rq
```

`CN_TIMEOUT_SECONDS` 允许 5–60 秒，`CN_MAX_BYTES` 允许 1,000,000–30,000,000 字节，限制单响应解码后的大小。A 股功能不依赖 `SEC_USER_AGENT` 或模型 Key；实际网络仍须允许访问固定来源域名。UI 市场选择仅改变搜索/导航上下文，不会修改后端数据模式或权限。

升级已有实例时，先用安装好后端依赖的 Python 从项目根执行迁移，再重启 API 和 worker，前端部署重新构建：

```sh
python scripts/manage.py migrate
python scripts/manage.py serve
# 另一个 Linux/WSL 终端
python scripts/manage.py worker
# 前端开发终端
cd frontend
pnpm dev
```

已有 Windows/WSL 本机环境也可按 README 使用 `scripts/start_local.ps1` 恢复；它不安装依赖或替代迁移。生产保持 PostgreSQL 和 RQ；SQLite/inline 只允许显式开发测试，不应称为真实队列部署。

UI 操作顺序：

1. 在设置页输入 `LOCAL_ADMIN_TOKEN` 并用于本次会话；不是模型 API Key，刷新页面后需要重新载入。
2. 首页或顶部搜索选择“A 股 · CN”。首次目录为空时点击“更新 A 股目录”，等待实际任务成功。
3. 输入中文简称、`600519`、`600519.SH` 等，确认名称、交易所和证券代码后进入公司页。
4. 点击“同步最新 A 股资料”，观察排队/运行/成功或失败状态。选择年度或年初至今及具体报告期。
5. 点击指标卡片或“查看来源”核对精确值、来源页与计算依据；“财报与公告”打开来源站点PDF，或进入正文研究准备文本、检索页码证据；模型生成需已验证的配置。

本地管理 CLI 可用于首次同步和排错：

```sh
python scripts/manage.py cn-refresh-directory
python scripts/manage.py cn-sync --symbol 600519.SH
python scripts/manage.py cn-sync --symbol 000001.SZ
```

CLI 创建持久化任务后在当前进程执行并返回结果；它与浏览器通过 RQ 入队是两种执行入口。一次 CLI 成功不能代替实际 RQ worker 验收。

Compose 的 API、worker 使用同一组 `CN_DATA_MODE`、超时和大小限制。首次或更新配置后按部署指南重新创建服务；容器里的主机地址与裸机不同。数据库迁移和 Compose 配置可用不等于完整容器启动已经验收，实际结果仍以测试记录为准。

## 可信本地归档

`cn_snapshot` 用于部署者已经取得的真实响应，**不是联网失败时的自动 fallback**。当前源码包不附带本次抓取的东方财富 raw 数据，也没有把合成测试金额当真实演示归档。先为目标数据库配置 `CN_DATA_MODE=cn_snapshot`，执行迁移，再准备目录清单与证券清单：

```sh
python scripts/manage.py cn-import-archive --manifest /absolute/path/directory-manifest.json
python scripts/manage.py cn-import-archive --manifest /absolute/path/company-manifest.json
```

先导入真实公司目录，证券清单的 `scope` 必须已在该目录中。清单顶层结构为：

```json
{
  "source_kind": "cn_snapshot",
  "scope": "directory",
  "resources": [
    {
      "kind": "directory",
      "file": "directory-response.json",
      "url": "https://www.cninfo.com.cn/new/data/szse_stock.json",
      "fetched_at": "2026-11-04T00:00:00Z",
      "sha256": "替换为真实文件的64位SHA-256",
      "metadata": {"provider": "cninfo", "request_method": "GET"}
    }
  ]
}
```

这是清单格式示例，不含可导入的真实数据；文件、哈希和抓取时间必须换成实际值。证券清单将 `scope` 设为带交易所代码，包含 `indicators`、`income`、`balance`、`cashflow` 的全部响应页及可选公告页。元数据应保留实际请求参数、供应商、模板和分页信息。

导入器限制清单 100,000 字节、资源 1–30 项，每个文件受响应大小限制；只读取清单目录内的文件，拒绝路径越界，核对 SHA-256、带时区时间戳及固定 HTTPS 来源主机/路径。任何失败回滚本次导入。哈希只证明文件与清单一致，不能证明清单作者或数据本身真实，因此只导入可信、实际获取并核对过的本地归档。

## 安全、失败与验收

网络客户端只访问代码内固定端点，参数由后端生成，不接收用户提供的远程 URL；不跟随重定向、不采用环境代理，使用共享 Redis 限速。403/429 会进入冷却并考虑 `Retry-After`，不会换 IP 或循环重试绕过限制。限速服务不可用时停止外联。异常 JSON、重复键、非有限数字、200 HTML/WAF 和超大响应被拒绝。

公告PDF从已保存索引的受控地址下载，后台隔离解析文本，不接受任意URL或提供通用PDF代理。页面按文本显示公司、公告与证据，写操作及任务/报告查询检查服务器端身份；管理员令牌仅在会话内存，不进入URL、localStorage或Redis任务内容。单用户权限及HTTPS边界保持，当前并非公开多租户认证系统。

常见失败包括目录未更新、未知模板、币种/证券不符、分页变化、限流、旧模式绑定冲突、队列不可用和来源清单缺页。先读取具体任务错误，再核对部署模式及服务；不要通过删除模式绑定、放宽来源验证或填充假数让页面显示成功。

财务与PDF/模型测试使用明确标识的隔离夹具，真实在线获取、PG/RQ、浏览器及外部模型结果分开记录。PG并发测试不以SQLite代替。实际完成情况见[测试记录](TEST_RESULTS.md)和[任务清单](TASKS.md)；真实模型及推论语义支持仍需单独验收。
